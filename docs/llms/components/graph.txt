# Graph

Node-link diagram canvas. ER diagrams, dependency graphs and call graphs from one component,
driven by field-mapped data rather than a fixed schema type.

```svelte
<script>
  import { Graph } from '@rokkit/graph'
</script>

<div class="relative h-[600px]">
  <Graph {nodes} {edges} {fields} bind:value />
</div>
```

The canvas fills its nearest positioned ancestor, so **give it a `relative` box with a
height** or it collapses.

## Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `nodes` | `unknown[]` | `[]` | Any row shape — mapped by `fields`, never required to match a schema type |
| `edges` | `unknown[]` | `[]` | Any edge shape — endpoints resolved through `fields.source` / `fields.target` |
| `fields` | `GraphFields` | `{}` | Dotted-path map from your shape to the canonical model |
| `state` | `GraphState` | — | Share one state across Graph / EntityView / EntitiesView |
| `layout` | `'cluster' \| 'flow' \| 'neighborhood' \| 'points' \| 'radial' \| 'structure' \| 'sunburst' \| 'world' \| LayoutFn` | `'flow'` | A built-in by name, or your own pure `(model, options) => LayoutResult` |
| `density` | `'names' \| 'keys' \| 'full'` | `'keys'` | How much of each node's row list a card shows. `cluster` and `flow` — see Applicability. **Bindable** |
| `arrange` | `'untangle' \| 'a-z'` | `'untangle'` | Cluster ordering |
| `groupBy` | `'group' \| 'kind'` | `'group'` | Outer grouping axis |
| `groupTint` | `boolean` | `false` | Paint each CARD with its group's ramp. Schema stays visible in a layout with no cluster boxes |
| `nestBy` | `'group' \| 'kind'` | — | Subdivide each cluster by a second axis |
| `edgeStyle` | `'curved' \| 'orthogonal'` | `'curved'` | Connector geometry |
| `focus` | `string \| null` | `null` | `neighborhood` only — the node to centre. Defaults to the selection |
| `depth` | `number` | `1` | `neighborhood` only — how many hops out from the focus |
| `sizeBy` | `string` | `'degree'` | `points` / `world` — the measure area encodes. `degree`, `weight`, or a `measures` key |
| `sizeScale` | `'linear' \| 'log'` | `'linear'` | `points` only — how the measure maps onto area |
| `focusPath` | `string[]` | `[]` | `world` / `sunburst` / `structure` — the subtree drawn as the whole canvas, as the DATA path. **Bindable**: drilling moves it |
| `levels` | `number` | `2` | `world` / `sunburst` — how many levels below the focus to materialise |
| `radialMode` | `'tree' \| 'dendrogram'` | `'tree'` | `radial` only — radius as depth, or every leaf on the rim |
| `value` | `string \| null` | — | Selected node id. Input and output both |
| `preset` | `GraphPreset` | — | `createGraphPreset({ groups, shades, using })` — colour for the open-ended GROUP vocabulary |
| `mode` | `'light' \| 'dark'` | `'light'` | Which shade ladder the group ramp resolves against |
| `zoom` | `number` | `1` | Multiplier on the fit-to-container scale. **Bindable** |
| `zoomable` | `boolean` | `true` | Ctrl/pinch-wheel zoom and drag-to-pan. The BUTTON bar is `ZoomControl`, which you place |
| `arrows` | `boolean` | `true` | Arrowhead at each edge target instead of a plain dot |
| `label` | `string` | — | Accessible name. Derived from node/edge counts when omitted |
| `icons` | `Record<string, string>` | — | Icon class per node kind and row badge, merged over `DEFAULT_ICONS` |
| `onselect` | `(id: string \| null) => void` | — | Fires when a node is activated, and with `null` when the selection is cleared |
| `ondrill` | `(path, node) => void \| Promise<void>` | — | The reader opened a box. `node` is the declared node at `path`, `null` for a synthesised container. Return a promise while you load that level |
| `ondrillup` | `(path) => void \| Promise<void>` | — | The reader climbed out to `path`. Same promise contract |
| `onexpand` | `(id, node) => void` | — | The reader expanded a group node — see *Group nodes* |
| `oncollapse` | `(id, node) => void` | — | The reader collapsed a group back into one node |

### Drilling — loading a large tree one level at a time

`world`, `sunburst` and `structure` scope the canvas to `focusPath`. The reader drills by
opening a box, and you hear about it, so a tree too large to load at once (a whole monorepo
index) can be fetched level by level:

```svelte
<script>
  import { Treemap } from '@rokkit/graph'
  let nodes = $state(level0)          // what you have — never the whole tree
  let focusPath = $state([])

  async function ondrill(path, node) {  // node: the declared node there, or null
    nodes = await fetchLevel(path)       // return the promise: the canvas shows it pending
  }
  function ondrillup(path) {
    nodes = cache.get(path.join('/'))    // a level you still hold — no promise, no wait
  }
</script>

<Treemap {nodes} {fields} bind:focusPath {ondrill} {ondrillup} controls />
```

- **`path` is the DATA path**: the `path` your nodes carry, which is what you load by. An
  undeclared single-child wrapper folds out of the *picture*, but never out of the address a
  drill reports.
- **Send one level at a time.** The containers on the current `focusPath` are never folded,
  so a level you load on its own (a crate's modules, with nothing declaring the crate) still
  resolves.
- **`bind:focusPath`, or omit it.** Drilling moves it; a plain, unbound prop is yours, and
  re-rendering would put your old value back.
- **Pending and failure.** A returned promise dims the old level (`data-graph-pending`,
  `aria-busy`) and the drill bar says *Loading…*. Only the latest drill counts. A rejection,
  or a handler that throws, restores the previous level and shows why (`role="alert"`).
- **Drilling is not selecting.** `onselect` is not called, and the selection is left alone.
- **Gestures.** Click a container, or press Enter / Space on it (it is a button,
  "Open …"). A leaf selects on click and opens on double-click, or with the drill bar's
  *Open* after Enter selects it. A leaf opens only if you handle `ondrill`: with no loader,
  there is nothing below it to show.

The state behind it (`GraphState`): `drillPath`, `breadcrumbs`, `canDrill(box)`,
`drillInto(box)`, `drillOut(levels)`, `drillTo(ancestor)`, `pending`, `drillError`. Every
containment box carries `path`, `leaf` and `declared` (the id of the node it is, leaf or
container).

### Arcs — what the code declares against what the history reveals (#169)

`ArcDiagram` puts items on one shared, ordered axis and draws two relations over it: imports
arc to the **left**, shared commits to the **right**. The finding is a pair with an arc on one
side and none on the other: files that change together with nothing in the code tying them.

```svelte
<ArcDiagram nodes={items} edges={relations} {fields} above="cochange" controls />
<!-- fields: { label: 'name', group: 'group', relation: 'set' };
     relations: { set, source, target, weight, hidden? } -->
```

- **Which side.** By default structural edges go left and overlays (`overlay: true`) go right,
  since an overlay is observed rather than declared. `above` names the relation drawn right
  instead, so a host that labels each relation with a `set` needs no reshaping.
- **The axis.** One labelled box per item, top to bottom, ordered by group (first appearance)
  and then as given, and tinted by group. Readable at ~50 items; send a top-N, not thousands.
  Filtering never moves a box.
- **Thickness.** Each side scales its weights on its own, to its 95th percentile (clamped
  past it): an import count and a commit count are different units, and one outlying pair
  should not flatten the rest. The routed edge carries it as `strength`.
- **`hidden`.** The host flags a co-change pair with no import (`hidden: true`, or
  `fields.hidden`); rokkit computes no history and only styles it. It is drawn heavier, in the
  danger colour.
- **`showEdges: 'hidden'`** keeps only the hidden pairs. The control is `HiddenControl`, and the
  prop is bindable.
- **Legend.** On by default. It names the two sides and the hidden stroke. The side names
  come from the data: the relations drawn on each side, or *Declared* / *Observed* (from the
  locale) where a side's edges name none. `sideLabels={['Imports', 'Shared commits']}`
  names them yourself.
- **Styling hooks:** `data-edge-hidden`, `data-edge-side` (`below` / `above`),
  `data-graph-hidden-only`, `data-legend-side`, `data-legend-hidden`. The layout is `arcs`.

### Polymetric — three measures per box (#168)

`PolymetricTree` is Lanza & Marinescu's System Complexity view. A containment tree is drawn top
down, and each leaf is a box whose **width**, **height** and **shade** carry three independent
measures. `Treemap` encodes one measure as area; this shows three at once, so a narrow, tall,
dark box (a long file that keeps changing) reads differently from a wide, short, pale one.

```svelte
<PolymetricTree {nodes} widthBy="fns" heightBy="loc" colorBy="churn" controls />
<!-- nodes: { id, name, parent, measures: { fns, loc, churn } } -->
```

- **Containment from `parent` ids.** A node with no `path` gets one from its parent chain (ids,
  not labels). A parent that is not a node is kept as the container it names; a cycle is cut.
- **Channels.** `widthBy` / `heightBy` / `colorBy` each name a `measures` key, or `weight` /
  `degree`. All three are bindable. Width and height default to `weight`; omit `colorBy` for no
  shade. With `controls`, three pickers list the measures the data has.
- **Degenerate values.** Each channel scales to the 95th percentile of its values, so one huge
  file does not shrink every other box to a speck. A value past the cap draws at the maximum
  and is marked `data-graph-clamped` (a heavy edge on that side). A zero is a value and draws
  at the minimum. A **missing** measure also draws at the minimum but is marked
  `data-graph-missing` (dashed; a missing shade is hatched): it never passes for a zero.
- **Legend.** On by default, because three encodings are unreadable without a key. It names
  the measure on each channel and what its full extent stands for (`full at {cap}`). The state
  exposes the same as `graph.channels`, and the measures the pickers offer as
  `graph.measureKeys`.
- **Styling hooks:** `--shade` (0..1) on each leaf, `data-graph-missing`, `data-graph-clamped`,
  `data-legend-channel`, `data-graph-measure`. The layout is `polymetric`.

### Layers — the intended architecture, and what climbs it (#167)

`LayersDiagram` ranks nodes into horizontal bands by a **host-assigned** `layer` (0 at the top,
foundations at the bottom). rokkit computes no depth: you know the layering you intend.

```svelte
<LayersDiagram {nodes} {edges} layerLabels={['Interface', 'Domain', 'Infrastructure']} controls />
<!-- nodes: { id, name, layer }, edges: { source, target, conformance? } -->
```

- **Conformance.** Each edge is `down` (one layer down, conformant), `skip` (down more than
  one, drawn dashed), `up` (climbs, which is the violation, drawn in the danger colour) or
  `level` (within a layer). Send `conformance` and yours wins; otherwise it's derived from the
  two layers. An edge touching an unlayered node has none.
- **`showEdges: 'violations'`** keeps only the climbing edges. The control is
  `ViolationsControl`, and the prop is bindable. On a real codebase the conformant edges drown
  the signal.
- **Readability.** Each layer is a labelled full-width band, and a crowded one wraps into rows.
  Each layer is ordered under its neighbours in the layer above, to cut crossings. A node with
  no `layer` lands in an *Unassigned* band at the bottom.
- **Styling hooks:** `data-edge-conformance`, `data-graph-violations`. The layout is `layers`.

### Group nodes — condensing cycles (#166)

A dependency graph with cycles is unreadable. Collapse each strongly-connected component into
one node and what remains is a DAG. **You compute the components; rokkit draws them.** A group
is a node with `members`:

```js
nodes: [
  { id: 'api', name: 'api' },
  { id: 'scc:1', name: '3 modules in a cycle', members: ['tasks', 'indexer', 'watcher'], collapsed: true },
  { id: 'tasks', name: 'tasks' }, { id: 'indexer', name: 'indexer' }, { id: 'watcher', name: 'watcher' }
],
edges: [
  { source: 'api', target: 'tasks', weight: 320 },
  { source: 'watcher', target: 'tasks', weight: 4, weakest: true }   // the cheapest link to cut
]
```

- **Collapsed:** the members are hidden, and every edge touching one reroutes to the group.
  Edges inside the group vanish. Parallel edges fold into one, with weights summed and
  `data-edge-count` set.
- **Expanded:** the group gives way to its members and the edges among them. A group whose
  members are not in `nodes` yet stays as itself; answer `onexpand(id, node)` to load them.
- `collapsed` is the starting state, defaulting to `true` for any node with `members`.
  `oncollapse(id, node)` fires on the way back.
- **Gestures:**
  - a collapsed card has an inline **Expand · N** control (Enter / Space);
  - double-clicking a member folds its group;
  - the drill bar offers Expand / Collapse for the selection.

  Collapsing a group whose member is selected moves the selection onto the group.
- **Styling:** `data-graph-group`, `data-graph-collapsed`, `data-graph-member-of="<group id>"`,
  and `data-edge-weakest` (dashed, in the danger colour). Fields: `members`, `collapsed`,
  `weakest`.
- `GraphState`: `isGroup`, `isCollapsed`, `memberCount`, `groupOf`, `toggleGroup` and
  `groupAction`. The pure step is `condense(model, collapsed)`.

**`mode` does not infer itself.** Left at `'light'` in a dark app, the group ramp resolves
from the light ladder forever and every cluster keeps a pale fill — the canvas reads as light
whatever the app is set to.

**A supplied `state` must keep stable identity.** Context captures it once at init, so drive
the existing instance through its methods and `update()` rather than swapping instances.

## Interaction

| Gesture | Effect |
|---------|--------|
| Click a node | Select it; related nodes highlight, the rest dim |
| Click the background, or `Escape` | Clear the selection |
| Ctrl/⌘ + wheel, or trackpad pinch | Zoom the diagram (not the page) |
| Drag the background | Pan. Plain scroll works too |
| Click `+ N more` | Expand that ONE card in full |

Expansion is per node on purpose: a reader clicking "+3 more" is asking about that card, and
expanding all of them answers a question they did not ask.

### How interactions are wired — and how to add one

No graph element carries an event handler. What a press MEANS is state: `GraphState` writes
an intent onto each element (`data-graph-press` for a click and Enter / Space,
`data-graph-open` for a double-click, `data-graph-key` for what it is about), and one
delegated action, `interactions`, hands it to `GraphState.act(intent, key)`. The vocabulary
is a table in `state/intents.ts`: `select`, `toggle`, `drill`, `group`, `expand`, `crumb`,
`open-selected`, `group-selected`, `clear`. An unknown intent, or a key naming nothing, does
nothing; the DOM is not trusted.

Two more actions finish the set. `canvasNavigation` covers drag-to-pan and pinch-zoom, and
marks the paper `data-graph-panning` while a drag lasts. `choices` serves the controls: a
button's `data-graph-choice`, or a select's value, is reported to the control, which maps it
to its own type and calls its `onchange`. Each action is unit-tested on bare DOM.

## Words — every one is a message

Graph shows no English of its own. Every label, title, aria-label and sentence (state and
layouts included: "+ 3 more", "Layer 2", "Diagram of 5 nodes…") is a key in
`messages.graph` from `@rokkit/states`, flat so that a locale can replace one string:

```js
import { messages } from '@rokkit/states'

messages.register('de', { graph: { zoomIn: 'Vergrößern', more: 'noch {n}', layer: 'Ebene {n}' } })
messages.setLocale('de')
```

Templates name their values in braces. A spec registers a locale and checks every control,
the drill bar and the entity views; another scans the components and fails on any literal
word or DOM event handler.

## Reach for a named diagram first

`Graph` is the canvas: it draws what a layout hands it and ships **no chrome at all**. A named
diagram is the composition already made — one layout, the controls that mean something for that
picture, an opt-in legend. Same shape as `@rokkit/chart`, where `BarChart` and `LineChart` sit
over one `Plot`.

```svelte
<script>
  import { ErDiagram, CallTree, Treemap } from '@rokkit/graph'
</script>

<ErDiagram {nodes} {edges} {fields} controls legend />
<CallTree {nodes} {edges} {fields} levels={2} controls />
```

| Component | Draws | Controls it offers |
|-----------|-------|--------------------|
| `ErDiagram` | Table entities and foreign keys, ranked left to right | density, edge style, zoom |
| `DependencyDiagram` | Reads / writes / calls / contains | density, edge style, zoom |
| `CallTree` | A call graph as a radial tidy tree or dendrogram | depth, zoom |
| `Treemap` | Containment as nested rectangles | depth, zoom |
| `Sunburst` | The same containment as wedges | depth, zoom |
| `StructureDiagram` | A codebase: containment on a rim, calls bundled through it | depth (what sits on the rim), bundling, zoom |
| `Neighborhood` | One node and what reaches it | depth, edge style, zoom |
| `ArcDiagram` | Two relations over one axis: imports left, shared commits right, hidden pairs marked | only-hidden toggle, zoom; legend on by default |
| `PolymetricTree` | Containment top-down, each leaf a box: width, height and shade bound to three measures | width, height and shade measures, zoom; legend on by default |
| `DependencyMatrix` | A dependency structure matrix — cells above the diagonal are dependencies against the grain | none; row headers select |

`controls` and `legend` are both **off by default** — the default is the bare picture, because
a consumer embedding a diagram in their own shell wants their own chrome, not two sets.

### Composing your own

Every control is a component taking the value it drives, so a bespoke arrangement is the same
parts in a different box:

```svelte
<script>
  import { Graph, GraphState, DensityControl, ZoomControl, GraphLegend } from '@rokkit/graph'

  const graph = new GraphState({ nodes, edges, fields, layout: 'flow' })
  let zoom = $state(1)
  let density = $state('keys')
</script>

<Graph state={graph} bind:zoom />
<DensityControl {density} onchange={(v) => (density = v)} />
<ZoomControl {zoom} onchange={(v) => (zoom = v)} />
<GraphLegend state={graph} kinds relations />
```

A control stores nothing: it reports what was chosen and the caller owns the value. That is
what lets the same control drive a diagram, a URL parameter or a saved view.

## The default is `flow`, not `cluster`

A diagram's first job is showing how things reference each other, and `flow` makes that
readable off the geometry: columns ranked by direction, every edge leaving right and entering
left. `cluster` is one name away when schema boxes are what you want.

Schema is not lost by the change. `flow` has no cluster boxes — ranking and grouping compete
for the same axis — so `groupTint` paints each card's leading edge with its group's ramp
instead:

```svelte
<Graph {nodes} {edges} {fields} groupTint />
```

A spine rather than a fill, because a card's surface is already carrying its kind accent, its
selection state and its dim state, and a second wash over it muddies all three.

## Applicability — not every option reaches every layout

An option a layout ignores is worse than one that is missing: the control moves, the picture
does not change, and the reader concludes the VIEW is broken rather than that the control does
not apply. The package publishes which options bite, so your own control panel can ask:

```js
import { appliesTo, LAYOUT_OPTIONS } from '@rokkit/graph'

appliesTo('world', 'density')  // false — a treemap box has no row list to thin
LAYOUT_OPTIONS.world           // ['sizeBy', 'focusPath', 'levels']
```

| Layout | Options that do something |
|--------|---------------------------|
| `cluster` | `density` `arrange` `edgeStyle` `expanded` `groupBy` `nestBy` |
| `flow` | `density` `edgeStyle` `expanded` |
| `arcs` | `showEdges` `above` |
| `layers` | `density` `expanded` `showEdges` `layerLabels` |
| `polymetric` | `widthBy` `heightBy` `colorBy` |
| `neighborhood` | `edgeStyle` `expanded` `focus` `depth` |
| `points` | `edgeStyle` `sizeBy` `sizeScale` |
| `radial` | `edgeStyle` `sizeBy` `sizeScale` `radialMode` |
| `sunburst` | `sizeBy` `focusPath` `levels` |
| `structure` | `sizeBy` `sizeScale` `focusPath` `levels` `bundleTension` |
| `world` | `sizeBy` `focusPath` `levels` |

Two entries are not simply "what the layout function reads":

- `edgeStyle` is applied when an edge path is drawn, not by the layout — so it applies wherever
  a layout produces edges, which `world` does not.
- `neighborhood` takes no `density`: it builds cards at `full` unconditionally, because a
  portrait of one node's surroundings that hides the columns its edges land on defeats itself.

This is what a **named diagram** settles for you: `ErDiagram` offers density and edge style,
`Treemap` offers depth, and neither renders a control the other needs.

## Level of detail

The canvas publishes `data-graph-detail` from the **effective** scale (fit × zoom), and each
tier drops what has stopped being legible. Measured on a 1000-node graph fitted to 1440×900:
scale 0.047, so a 248px card renders 11.6px wide and a 12px label lands at 0.56px.

| Tier | Scale | Drops |
|------|-------|-------|
| `full` | ≥ 0.6 | nothing |
| `compact` | ≥ 0.32 | row types, row count, kind tag |
| `minimal` | ≥ 0.14 | rows, the more-row |
| `dot` | below | titles, cluster labels |

Hover or keyboard focus restores a node's label at any tier, counter-scaled so it is readable.

## Data attributes

Every visual hook is a data-attribute; the graph demo's API tab lists all of them (a spec keeps
that list complete against the theme CSS). The ones you reach for first:

| Attribute | Values |
|-----------|--------|
| `data-graph-node` | The node id, on a node CARD |
| `data-graph-node-id` | The node id, on a containment BOX — `world` renders a leaf as a box, not a card |
| `data-node-kind` | `table` `view` `matview` / `materialized_view` `function` `procedure` `trigger` `enum` — sets `--node-accent` |
| `data-node-group` | Your group names |
| `data-node-state` | `selected` `related` `dim` |
| `data-graph-node-kind` | The kind spelled out beside the icon |
| `data-graph-more-empty` | The density filter matched NO rows (a view at key density has no keys) |
| `data-edge-kind` | `reference` `dependency` (dashed) |
| `data-edge-relation` | The producer's own verb — dbd emits `reads` `writes` `calls` `member` |
| `data-edge-from` / `data-edge-to` | Endpoint ids — not otherwise recoverable from the DOM |
| `data-edge-state` | `highlight` `dim` |
| `data-edge-overlay` | On an overlay edge — co-change, a broken rule. Dotted in every style; `--edge-weight` (0..1) thickens it |
| `data-matrix-cell` | A `DependencyMatrix` cell; `data-matrix-from` / `-to`, `--cell-weight` |
| `data-matrix-above` | A matrix cell above the diagonal — against the grain, danger-filled |
| `data-matrix-row` / `data-matrix-block` | A matrix row header (a button) / a group's outline on the diagonal |
| `data-cluster-depth` | `0` outer, `1` nested inside it |
| `data-graph-detail` | `full` `compact` `minimal` `dot` |
| `data-graph-layout` | Active layout |
| `data-graph-node-shape` | `card` `dot` — what this layout draws a node as. The dot treatment keys on the SHAPE, so a new layout inherits it by declaring one |
| `data-graph-wedge` | One sunburst wedge, an SVG path. Reads the same group ramp a cluster box does |
| `data-row-badge` | `pk` `fk` `uq` `nn` |

### Retoning one kind

```css
/* [data-node-kind='table'] alone is (0,1,1) against a theme's (0,2,0) and silently loses. */
[data-style] [data-node-kind='table'] {
  --node-accent: var(--primary);
}
```

## Composing the schema views

`EntityView` and `EntitiesView` read the same `GraphState` from context, so selection is
shared with no wiring:

```svelte
<script>
  import { Graph, GraphState } from '@rokkit/graph'
  import { EntityView, EntitiesView } from '@rokkit/graph/schema'

  const graph = new GraphState({ nodes, edges, fields })
</script>

<Graph state={graph} />
<EntitiesView />   <!-- sortable table of every entity -->
<EntityView />     <!-- columns, indexes and relationships of the selection -->
```

## Accessibility

Every node is a real `<button>`, reachable by keyboard and activated with Enter or Space. The
accessible name lives on the `<svg>` holding edge geometry, not on the root — `role="img"`
makes its whole subtree presentational, so putting it on the root would hide every node from
assistive tech.
